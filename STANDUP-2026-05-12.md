# Standup notes — 2026-05-12

Token-efficiency work on the transcript pipeline. Starting point: ~1.36¢ / meeting (0.68¢ heavy extract + 0.68¢ light classify). Goal: <1¢.

## What I changed

### 1. Merged correction + extraction into ONE Gemini call
- Was: 2 sequential Gemini calls (correct the transcript → extract tasks).
- Now: 1 Gemini call. Reads the raw transcript, mentally corrects domain terms + speaker labels, emits tasks directly. Reports the corrections as scratch fields instead of a full rewritten transcript.
- Saving: ~60–70% on the transcript path. (No more big "corrected transcript" output — was 5–10k output tokens.)
- Behind `TRANSCRIPT_MERGED_EXTRACTION=true`.

### 2. Output prompt-bloat trim
- Compacted `domain_corrections` to `"from→to"` strings (one per unique correction) instead of verbose objects with each occurrence listed.
- Dropped per-task `context` field (verbatim transcript quote) — was diagnostic only, the whitespace check on it was lossy anyway.
- Trimmed the `## Output` section of the system prompt by ~1k chars (the schema now enforces shape, see #5).

### 3. Transcript noise cleanup (deterministic, no NLP)
- New `src/transcript_pipeline/transcript_cleaner.py`. Runs before the LLM sees the transcript.
- Strips pure-timestamp lines, bare speaker labels, blank-line runs.
- Collapses consecutive same-speaker utterances onto one line ("Santiago: yeah" / "Santiago: yeah it was good" → one line).
- Drops adjacent identical sentences inside the same utterance.
- Saving: typically 10–25% off transcript input tokens. Logs `Transcript cleaned: N → M chars` per meeting.
- Regex only — no spaCy, no content pruning.

### 4. Native Gemini SDK + explicit context caching
- Was: Gemini called via OpenAI-compat shim (`openai.OpenAI` with Gemini base URL). Gemini ignores OpenAI's auto-cache, so the ~7–10k-token system prefix (prompt + terminology + org chart) was paid in full on every call.
- Now: native `google-genai` SDK. The stable system prefix is uploaded once via `client.caches.create()` with a 1h TTL and reused across every meeting in that window. Cached input tokens billed at ~25% of standard rate.
- Cache key is SHA256 of the prefix → an Org Chart or terminology change naturally produces a fresh cache. NOT_FOUND on expiry triggers one retry without the stale handle.
- Falls back cleanly to OpenAI-compat for any non-Gemini model.

### 5. Structured output via `response_schema`
- New `MergedExtractionOutput` Pydantic model in `src/transcript_pipeline/schemas.py`.
- Native Gemini call uses `responseSchema=MergedExtractionOutput` + `responseMimeType="application/json"`.
- Removes the need for the model to "remember" the JSON shape from the prompt, cuts malformed-JSON failures, enables the prompt trim in #2.
- Schema is portable — same Pydantic model would feed OpenAI's structured-output format if we swap models.

## Expected impact
- #1 alone: ~60–70% off the extraction call.
- #2–#5 stack on top: caching is the biggest single lever among them.
- Together should clear the <1¢ / meeting target once #4 hits the prod cache TTL.
